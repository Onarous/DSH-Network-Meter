# dsh-plugin-network-meter

Считает трафик, который DeepSeek Harness отправляет и получает.

Плагин измеряет каждый исходящий HTTP-запрос Host и показывает, сколько байт ушло
и сколько пришло. Панель ведёт с **текущей скоростью передачи**, чтобы видеть,
что происходит прямо сейчас; итоги сессии остаются ниже как контекст.

## Зачем

Сессия DSH ходит к провайдеру модели, к API веб-поиска, к MCP-серверу и к рынку
плагинов. Ни один из этих потоков не виден в интерфейсе. Этот плагин делает их
видимыми: с какой скоростью идут байты сейчас, сколько всего ушло, сколько
вернулось, на какие хосты.

## Скорость, а не итог

Итог сессии отвечает на вопрос «сколько всего», растёт бесконечно и ничего не
говорит о текущем моменте. Поэтому главное число — **скорость по скользящему
окну** (по умолчанию пять секунд): байты в секунду, посчитанные по запросам,
завершившимся внутри этого окна.

Делит скорость сам размах окна, поэтому запрос, завершившийся полсекунды назад,
считается как полсекунды трафика, а не как пять. Когда трафик прекращается,
скорость падает до нуля, а итоги остаются на месте.

## Установка

Через Plugin Manager в боковой панели Web или из командной строки:

```bash
dsh plugin install dsh-plugin-network-meter
```

Вручную — добавьте пакет в `dependencies` профиля и его же в
`dsh.profile.bundles`:

```json
{
  "dependencies": {
    "dsh-plugin-network-meter": "github:Onarous/DSH-Network-Meter"
  },
  "dsh": {
    "profile": {
      "bundles": [
        "@deepseek-ai/dsh-base",
        "dsh-plugin-network-meter"
      ]
    }
  }
}
```

После правки списка бандлов DSH нужно перезапустить.

## Как это работает

В DSH нет внедряемого HTTP-транспорта: в реестре сервисов Cordis нет ни
`http`, ни `fetch`, ни `transport`. Исходящий код вызывает глобальный `fetch`,
поэтому плагин оборачивает `globalThis.fetch` и считает вокруг него. Это тот же
приём, который использует сам `dsh-experimental-inspector`.

Обёртка прозрачна по построению:

- `input` и `init` передаются дальше **по идентичности**, поэтому `init.dispatcher`,
  `init.signal`, `init.redirect` и прочие опции доходят до undici Node'а нетронутыми,
  а политика прокси из `dsh-http-proxy` продолжает работать как прежде;
- тело запроса измеряется без чтения: объект `Request` измеряется через клон;
- тело ответа измеряется через клон, который разбирается в фоне, — поток вызывающего
  не трогается, потоковые ответы (SSE) продолжают течь;
- ошибка измерения никогда не ломает измеряемый запрос; тело неизвестного размера
  считается как `0` и увеличивает счётчик `unmeasured`, чтобы занижение было видно,
  а не молчаливым.

## Настройки

| Поле | По умолчанию | Значение |
|---|---|---|
| `observe` | `true` | Оборачивать ли `globalThis.fetch`. При выключенном плагин остаётся подключённым и его эндпоинт отвечает, поэтому интерфейс может сообщить, что наблюдение выключено. |
| `maxHosts` | `25` | Сколько хостов показывает снимок. |
| `maxRecent` | `60` | Сколько последних запросов хранит плагин. |
| `refreshMs` | `1000` | Как часто браузер опрашивает Host, в миллисекундах. |
| `rateWindowMs` | `5000` | Скользящее окно, в котором считается текущая скорость, в миллисекундах. Короткое окно следит за моментом, длинное сглаживает дрожание одного ответа. |

## Эндпоинты

### `GET /api/network-meter/stats`

Отдаёт текущий снимок: отправленные и полученные байты, число запросов, ошибки,
разбивку по направлениям и хостам, список последних запросов.

### `POST /api/network-meter/reset`

Обнуляет все счётчики и отдаёт свежий снимок.

## Что попадает в счёт, а что — нет

**Считается** — каждый запрос Host, сделанный через глобальный `fetch`: вывод
модели, discovery моделей, веб-поиск, DeepSeek web API, MCP поверх
streamable-HTTP и рынок плагинов.

**Не считается** — и почему:

- прямой путь `dsh-web-fetch-http` создаёт собственный undici `Agent`, чтобы
  закрепить адрес, и до глобального диспетчера не доходит; его путь через прокси
  использует глобальный и считается;
- телеметрия OTLP пишет через `node:http`, минуя диспетчер;
- worker-потоки (`dsh-ptc-runtime`, workflow worker) имеют свою `globalThis`
  и свой диспетчер;
- запросы, которые **браузер** шлёт провайдеру напрямую, не проходят через процесс
  Host, и ни один Host-плагин их не увидит.

Бакеты направлений (`llm`, `web`, `mcp`, `plugin`, `other`) — это удобная разметка,
выведенная из URL, а не факт транспорта; незнакомый хост попадает в `other`, а не
угадывается в корзину.

## Тесты

```bash
pnpm install
node test/traffic.test.mjs         # байты, потоки, ошибки, опции транспорта
node test/rate-live.mjs           # текущая скорость: всплеск, спад, возврат к нулю
node test/end-to-end.mjs          # Host-часть целиком
node test/client.test.mjs         # слоты и рендер клиентского бандла
```

`test/loader-integration.mjs` поднимает плагин через настоящий реестр
`@deepseek-ai/cordis` на настоящем `dsh-host-webserver` — это ближайшее к рабочему
окружению DSH, что можно запустить вне приложения.
